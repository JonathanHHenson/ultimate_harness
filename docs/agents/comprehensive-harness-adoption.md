- Start with all portable components. Research the portable package and the target project's technical and team context before proposing edits. Account for each component and distinguish useful installation, native equivalence, inactive routing, and an approved omission. [Installation](../../skills_src/install-harness/SKILL.md#when-installing-the-first-harness) · [Evolution](../../skills_src/install-harness/SKILL.md#when-integrating-an-existing-harness)

Present its effect on callers, data, and recovery separately from other changes. [Shared adoption guide](../../.agents/skills/build-harness/references/adoption.md)
- Separate each material choice and each evidenced project-specific skill or validation in the form. Preserve explicit prior answers and use conditional pages for newly exposed choices. The shared guide ships in the harness-maintenance component, which declares the form skill as a dependency for intact adoption. [Export catalog](../../skills_src/harness-files.toml)

- Keep the catalog assessment in the research notes and use the form prologue for scope, settled constraints, and one relevant project task. Collect every answerable preference on the first page. Ask about conditional activation separately and apply it only with an approved, satisfied prerequisite. Follow up when the answers create a new material decision. [Shared adoption guide](../../.agents/skills/build-harness/references/adoption.md#when-collecting-decisions)
