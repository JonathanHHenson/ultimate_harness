# Design interviews and form clarification

## Design interview

Pin the four skills from the reviewed Matt Pocock release. Grill With Docs invokes Grilling and Domain Modeling. Wait What is invoked when a human asks for clarification. The contextual instructions route factual discovery to repository evidence, design questions to the Human Interaction form, and decisions to the target’s existing glossary and decision process. The bundles carry the upstream instructions and MIT notice for use during adoption. The target uses the pinned CLI to generate its own lock when adopting those files.

Route the interview from the active agent instructions before every project change. Group related edits in one pass. Resolve factual questions from the repository and use the human's previous decisions where they apply. If an open decision affects the change, collect the answer before making related edits. Reopen the interview for materially expanded work, including edits to the interview workflow itself. Keep local session preparation and read-only investigation available. Both portable workflows use the bundle to agree on the plan and add or merge the trigger when the interview is adopted.

## Form interaction

Add a native dialog with an optional feedback field. A request is a separate user event for the current active page. The server saves exactly one pending event, exposes it via the existing `wait` CLI, and pauses answering until an authorized agent replaces the page with `revise`. The agent uses Wait What to rewrite the prologue, labels, or help. It keeps the same decision schema, including field IDs, requiredness, and option values. The server enforces that boundary. Neither requesting nor revising submits a page.

A monotonic revision orders browser states, distinguishes multiple explanations of the same page and rejects stale browser requests. Browser draft values remain local and are restored on same-page revision. The server reuses the current URL, authorization and origin checks. Requests and revisions refresh the idle timeout and respect the hard lifetime. The server releases the pending event after a valid revision or termination.

## Verification

Check both portable packages and lock records. Exercise clarification before a single-page submit and after a multi-page transition. Cover blank and nonblank feedback, stale revisions, unauthorized requests, invalid replacements and expiration through the loopback interfaces. Test keyboard dismissal, waiting, rewritten text, preserved draft state, and final submission in a browser.
